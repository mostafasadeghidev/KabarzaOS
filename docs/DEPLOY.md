# Deploying KabarzaOS

Three services are involved: the **app** (Next.js), **PostgreSQL 17** and
an **S3-compatible object store** (MinIO). All three are defined in
`docker-compose.yml`.

These happen automatically — there is no manual step for any of them:

- **Database migrations** run when the app boots. If a migration fails the
  container does not start; that is deliberate.
- **The storage bucket** is created on first use.
- **Secrets** — `SESSION_SECRET` and `CRON_SECRET` are generated on first
  boot and kept in the `app_data` volume, so they stay stable across
  restarts. **No environment variable is required**, which is what lets
  GUI deployment tools work without any manual configuration.

---

## Option 1 — one command

```bash
git clone https://github.com/mostafasadeghidev/KabarzaOS.git && cd KabarzaOS
docker compose up -d --build
```

Then open the address. The **setup wizard** creates the owner account.

Updating is the same command:

```bash
git pull && docker compose up -d --build
```

`install.sh` wraps this and adds three conveniences: it generates a unique
database password instead of using the built-in default, picks a free host
port if 3000 is taken, and waits until the app reports healthy before
printing the URL.

```bash
bash install.sh                    # asks for the domain
bash install.sh team.example.com   # or pass it directly
```

**TLS:** the app publishes on all interfaces by default, which is what
deployment tools expect — their proxy usually runs in another container
and cannot reach the host's loopback. Put a reverse proxy (Caddy,
Traefik, nginx) in front for HTTPS, and set `BIND=127.0.0.1` if you want
the port closed to everything but that proxy.

**Port:** defaults to 3000. Override with `APP_PORT`.

## Option 2 — Coolify

1. **+ New → Application → Docker Compose**, point it at this repository.
   `docker-compose.yml` is picked up by default.
2. Under **Environment**, set `APP_URL=https://your-domain` — that is all.
3. Assign the domain; TLS is automatic.
4. Open it → setup wizard.

**Do not set secrets by hand.** `SESSION_SECRET` and `CRON_SECRET` are
generated by the container and stored in the `app_data` volume. The
database and object store have no published ports, so they use internal
defaults.

Any variable you do set takes precedence over the generated one.

⚠️ **Do not delete the `app_data` volume.** Losing it changes
`SESSION_SECRET`, which signs everyone out. No data is lost, but everyone
has to log in again.

The `cron` service is part of the compose file and ticks every five
minutes on its own. If you deploy from the Dockerfile instead, add a
scheduled task:

```bash
curl -fsS -H "x-cron-secret: $CRON_SECRET" http://localhost:3000/api/cron/tick
```

Without the tick, reminders, meeting notifications, abandoned-timer
alerts, the daily digest and automatic cleanup never run. Its health is
visible under Settings → System (last tick, plus a staleness warning).

## Environment variables

Everything required is generated. This table is for manual setups.

| Variable | Required | Notes |
|---|---|---|
| `APP_URL` | recommended | Public address; used in notification links |
| `SESSION_SECRET` | — | Generated on first boot, kept in `app_data` |
| `CRON_SECRET` | — | Same; the `cron` service reads the same file |
| `DB_PASSWORD` | — | Has an internal default. Changing it after the first boot does not work — Postgres fixes the password at initdb |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | — | Internal defaults; the store has no published port |
| `APP_PORT` | — | Host port, default `3000` |
| `BIND` | — | Bind address, default `127.0.0.1`; use `0.0.0.0` without a proxy |
| `DATABASE_URL` | — | Only outside compose; built automatically inside |
| `S3_ENDPOINT` | — | Only outside compose; `http://storage:9000` inside |
| `S3_BUCKET` / `S3_REGION` | — | Default `kabarza` / `us-east-1` |
| `APP_TIMEZONE` | — | Default `Asia/Tehran` |
| `DEFAULT_LOCALE` | — | Default `fa` |
| `SMTP_HOST/PORT/USER/PASSWORD/FROM` | — | Without these, email notifications stay silently off |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_BOT_USERNAME` | — | Without these, the Telegram channel is hidden |

## First user

Open the address and the wizard asks for name, surname, email, username
and password, then signs you in. After that the route is closed
permanently. For scripted installs see `POST /api/setup` in
[`ACCOUNTS.md`](ACCOUNTS.md).

⚠️ **Do this immediately after deploying.** Until a user exists, anyone
who knows the address can claim ownership — the same model the previous system and
Gitea use.

## Operations

- **Backups — two things:** a Postgres dump and the S3 bucket
  (attachments, receipts, avatars). The database alone is not enough.
  ```bash
  docker compose exec -T db pg_dump -U kabarza kabarza > backup.sql
  ```
- **Logs:** `docker compose logs -f app`
- **Health:** `GET /login` must return 200 — that is what the healthcheck
  measures.
- **Database and object store publish no ports**; they are reachable only
  from the compose network. The MinIO console is closed as well, since the
  bucket is created automatically. To reach it temporarily:
  ```bash
  docker compose run --rm -p 127.0.0.1:9001:9001 storage
  ```
- **Language and calendar** are per-user; nothing is needed server-side.
